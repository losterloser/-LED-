# FPGA 音频工程复现与验收

## 适用范围

适用于 Vivado RTL 工程，尤其是流式音频、FFT、屏幕与地址灯显示，以及电脑通过串口接收音频并回传结果的系统。换题目时可保留报告校验器、复现流程和验收模板；板型、引脚、时钟和外设初始化必须重新核对。

## 使用方法

可将本目录复制到支持 SKILL.md 的工具技能目录，也可不安装，直接让协作模型读取 SKILL.md。本技能不要求本项目的曲库和硬件才能运行报告校验。

```powershell
python skill/fpga-audio-reproduce/scripts/check_reports.py --root . --config build/config/report_checks.json
```

复用到其他工程时，可复制 `assets/report-checks-template.json`，把报告相对路径和资源上限换成自己的值；示例上限对应 Z7010，不能沿用到不同器件。提示词、流程与失败清单分别位于 references/；验收 JSON 骨架位于 assets/。

## 已验证的效果与经验来源

- 同一份校验器能读取本工程原始实现报告，得到 WNS 0.379 ns、WHS 0.025 ns 和资源占用。
- 用负 setup、负 hold、资源超预算、缺失报告与未约束端点的样本检查“应该失败”的行为。
- 项目曾因 Vivado 调试核路径过长而需要临时短路径；流程保留此适配，而不是要求复用者使用原电脑盘符。
- 出现过下载器可见但芯片不可见，以及 MIC 正确歌名随后丢失；技能要求分别定位物理链路和时间连续证据，不能用缓存标题掩盖失败。
- 用户明确确认采集通过、彩条正确和逐灯自检后，只更新对应验收项，没有自动扩大为完整系统通过。

## 失效条件

未安装适用 Vivado 或 IP 不兼容时，不能完成硬件重建；新器件和外设不匹配时不能沿用原 XDC；报告格式变化时需调整解析器。缺少录音或真实外设观察时，软件回放不能证明现场识曲效果。模板不代替原始日志，也不为任意音频质量保证识别成功。
